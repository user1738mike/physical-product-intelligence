See the [API permission matrix and schemas](integrations-api.md) and [delivery/security procedures](webhook-delivery.md). Only `catalog:read`, `assessments:read` and `assessments:export` are accepted. A credential belongs to one organization and an active owner/admin issuer; every request rechecks role, revocation, organization and policy. Wildcards, mutation/upload/billing/admin access and tenant selection through caller data are rejected. Members cannot manage integrations; foreign resources are 404. Staff has no HTTP tenant bypass.

Plan extensions attach only to newly published unassigned versions >=2, without changing immutable historical plan definitions or inventing prices. Missing extensions fail closed. Finite active-credential/enabled-destination allowances constrain new issuance/enabling; existing history is retained. Operational traffic/delivery retries do not become charges. Historical reads follow the documented last-ended-policy boundary while new work requires current access.

## D. Security findings and boundaries

API secrets have 256 random bits, a public lookup UUID and only a one-way verifier in PostgreSQL. One-time values are absent from later metadata, URLs, logs and persistent browser storage. Shared counters/leases survive rotation and process boundaries; admission includes current issuer authorization. The browser runner now creates failure reports/console output only inside its disposable container, removes bearer/signing values and fixture passwords, then copies sanitized artifacts to the host. Screenshots occur after reveal dismissal; trace/video/login screenshots are disabled.

The current Standard Webhooks 1.0.0 specification and OWASP SSRF guidance were read before implementing symmetric `v1` signing. Endpoint keys are uniquely derived from a dedicated versioned root, with bounded overlap and immediate compromise replacement. Root configuration is absent in normal production defaults, never borrowed from OpenAI, Django or payments. Tests check exact body/ID/timestamp signing, altered/expired inputs, rotation and reference-consumer deduplication.

Normal outbound transport requires exact approved HTTPS hosts/443, validates every DNS answer on every attempt, rejects non-public/reserved IPv4/IPv6 and mapped/tunnel bypasses, pins the socket while retaining SNI/certificate verification, follows no redirects and bounds DNS/concurrency/time/response size. Public-network destination TLS/egress testing is **documented/not executed**. The live demonstration transport is a separately guarded loopback sender only in an isolated synthetic database; it does not certify the real HTTPS transport or contact a customer host. Production test-transport configuration is rejected.
