## B. Implementation

- Deployment: backend image defaults to bounded Gunicorn; local `compose.runtime-check.yaml` selects Gunicorn/standalone Next for real runtime checks. Compose now has init/restart/graceful policies, configurable loopback backend port, non-root bind-mount UID/GID support and frontend dependency on backend readiness. Separate `compose.production.yaml` describes immutable images, resource limits, read-only roots, tmpfs/private volume and no published backend/DB ports. It expects separately provisioned managed DB, scanner and TLS ingress; it was not deployed.
- Configuration: exact hosts/HTTPS origins, strong non-default DB password, absolute private root outside static, certificate-verified PostgreSQL TLS, restricted proxy CIDRs and opt-in HSTS subdomain/preload. Untrusted peers cannot supply scheme/client-IP authority. Production readiness rejects elevated/owner-assumable runtime DB identities; migration credentials remain separate deployment responsibility.
- Recovery: operator `backup_bundle`/`restore_bundle` commands protect new destinations, require exact identity/maintenance confirmation, use custom logical DB dump plus private bytes/count/checksum manifest, and restore only to a new empty `ppi_restore_…` database/new matching private root. No clean/overwrite/delete/promotion behavior exists. Credentials use restricted subprocess environment, never argv/logs. Dump hashing streams rather than loading the whole dump. A reproducible synthetic isolated drill and normal restart comparison script are included.
- Jobs: existing durable explicit synchronous state/lease/retry/review architecture is retained for a small deployment. PostgreSQL advisory admission serializes a DB-wide default cap of two fresh AI extractions, with one per tenant; cap is bounded 1–8. Provider work holds no DB admission lock. Existing 90-second recovery lease, three-attempt limit, cancel/late-output discard, current permissions/source/target checks and idempotent persistence remain. Automatic scheduling/recovery and exactly-once billing are not claimed. Deterministic engine semantics were not changed.
- Abuse: shared PostgreSQL atomic fixed-window counters replace process-local throttles. Login/register use trusted peer; ingestion/extraction/assessment writes use user plus authorized tenant. Multi-subject denial rolls back admission, unknown foreign org selectors cannot select counters, 429 includes wait, and DB failure yields sanitized fail-closed 503. Bounded GETs retain query budgets. Expired-counter pruning is operator dry-run by default.
- Storage: existing private tenant-scoped/integrity-checked files and bounded format/parsing controls are retained. A private ClamAV INSTREAM hook accepts only a complete clean reply, bounds bytes/response and applies a five-second socket/deadline policy; infection, timeout and unavailability fail closed. No daemon, signature freshness, object-storage migration or retention executor is claimed. Policies and filesystem/single-host limitations are documented.
- Observability: liveness remains DB-independent; readiness includes migrations and production dependency policy. Logs emit fixed events, sanitized correlation values and route templates, omitting raw unknown paths/query/header/body/provider/exception content. Committed audit actions/outcomes cover material/security lifecycle events. Operator-only status reports role policy, jobs/states/age and configuration-only AI availability, explicitly not provider reachability. No public metrics or achieved SLO is claimed.
- CI: locked installs plus pip consistency, explicit formatting config for backend/scripts, synthetic production config check, PostgreSQL tests/migrations/OpenAPI, frontend tests/checks/build, core/SDK image matrix, non-root/env/private-file checks, actual production-server Compose smoke, correct migrate-before-readiness ordering and optional manual dispatch. No API key/live request is required. Hosted results for these uncommitted changes do not exist.
- AI validation: separate opt-in `check_ai_provider` reuses the current adapter/schema with one tiny synthetic request only after explicit authorization. Ordinary invocation is inert. Mocked gate/SDK tests require no real credential. The versioned 18-case `synthetic-spec-v1` dataset and `validation-boundary-v1` harness exercise schema, grounding, numeric/unit pairing, unsupported/unknown fields, conflicts, fabricated references and adversarial/misleading context; existing service tests cover provenance/review/application. Result label is `recorded-mock-fixtures-v1`, with zero provider calls. This measures validation boundaries, not model quality.

Full operational configuration, protected recovery procedures, role/grant responsibilities, retention/incident policy and release checklist are in [deployment and operations](deployment-and-operations.md). [ADR 0012](architecture-decisions/0012-small-deployment-operational-controls.md) records the small-deployment trade-offs.
